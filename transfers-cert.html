Hotelbeds Transfers — flujo certificación

Página técnica para pruebas y evidencias (screenshots / vídeo). Cubre las mismas operaciones que Postman contra el proxy GET/POST /api/hotelbeds-transfers: disponibilidad simple (GET), multi (POST), booking (POST), detalle (GET o POST), cancel (POST), ping. Credenciales compartidas con Hotels (test/prod según HOTELBEDS_ENV). Para peticiones idénticas a Postman usa el JSON avanzado del booking o el multi con filtros vehicle/type/category. Tras confirmar una reserva en test, anota la referencia y usa Cancelar si procede.

1. Disponibilidad (GET)

Tipos de punto (doc HB): IATA, ATLAS, GIATA, GPS, PORT, STATION. En GPS, toCode es lat,lon (coma decimal). En GIATA, fromCode/toCode son el id GIATA.

1b. Disponibilidad Multi (POST)

Hasta 20 rutas en una petición. Cada id es fromType/fromCode/toType/toCode (ej. hotel Universal Barcelona → aeropuerto: ATLAS/57/IATA/BCN). Los códigos PORT/… deben existir en el catálogo Hotelbeds; si no, usa IATA/BCN para el aeropuerto. Reutiliza ocupación e idioma de la sección 1.

Query opcionales (misma API que Postman; vacío = omitir):

Servicios (elige uno para rellenar rateKey abajo)

Respuesta API

JSON del proxy (simple, multi, booking, detalle o cancel). Revisa ok, httpStatus y data.

Pulsa «Buscar disponibilidad (simple)» o «(multi)» para probar el proxy.

2. Confirmación (POST booking)

Pega el rateKey del servicio elegido. Marca segundo tramo para ida y vuelta (dos rateKey distintos, tras dos búsquedas). O usa el JSON avanzado para igualar Postman al 100%.

Opcional — cuerpo booking completo (sustituye el formulario si es JSON válido; debe incluir language, holder, transfers como en Postman). clientReference se recorta a 20 caracteres (límite Transfer API). Déjalo vacío para usar solo el formulario.

3. Detalle de reserva (BookingDetail)

Consulta por referencia HB (mismo localizador que tras el booking o en el email). Usa el idioma de la sección 1. Equivale a Postman: GET …/bookings/{lang}/reference/{ref} vía proxy.
